## 🔬 В двух словах: суть исследования

* **Инкапсуляция данных в медиаконтейнер VP8.** Исследование метода передачи произвольных потоков данных внутри полезной нагрузки сжатых видеокадров WebRTC через инфраструктуру видеоконференцсвязи (Яндекс Телемост).
* **Пользовательский контекст без системных привилегий.** Работа исключительно на уровне прикладных API браузера Chrome (Offscreen Document, Web Worker, WebAssembly) без требования системных сетевых адаптеров или прав администратора.
* **Строгая изоляция сетевого контекста (Network Context Isolation).** Предотвращение паразитных сетевых утечек и обеспечение чистоты эксперимента в тестовом профиле через нейтрализацию фоновых сокетов (WebRTC STUN suppression, Service Worker interception).
* **Высокопроизводительный транспортный конвейер.** Оптимизация пропускной способности через мультиплексирование KCP + Smux v2 (окно 4 МБ), нативное SIMD-кодирование, пул keep-alive сокетов (240 соединений) и интеллектуальное кэширование ответов в ОЗУ.

## 🎯 Цель исследования

**Изучить характеристики пропускной способности, задержек и стабильности кастомного транспортного протокола поверх видеосессий WebRTC.**

Традиционные схемы передачи данных в браузерных расширениях ограничены стандартными возможностями WebSocket или WebTransport. Проект **olcRTC Research** исследует гипотезу:
1. Сетевые запросы HTTP/HTTPS и GraphQL инкапсулируются в транспортный протокол **KCP** с контролем целостности (CRC32C) и гарантированной доставкой.
2. Фрагменты KCP встраиваются в полезную нагрузку видеокадров **VP8** с использованием стандарта `WebRTC Encoded Insertable Streams`.
3. Видеопоток передается через стандартную видеоконференцию Телемоста на тестовый серверный узел для демультиплексирования и замера метрик сетевой задержки.

## ⚡ Быстрый старт для разработчиков

### Изоляция сетевого окружения и границы тестового контура

Для обеспечения чистоты замеров и исключения паразитного фонового трафика в тестовом профиле Chrome при нажатии Connect активируются правила изоляции (Network Guard). Прямые сетевые запросы веб-приложений изолируются до момента установления связи через исследуемый WebRTC-канал. HTTP(S) запросы маршрутизируются через интерфейс отладки (CDP Fetch) в поддерживаемых вкладках и рабочих контекстах (Workers/Iframes); новые WebSocket и WebTransport сокеты подавляются во избежание прямых утечек. Доступ к системным координатам геолокации и предзагрузка DNS отключаются на уровне настроек сессии браузера для предотвращения рассинхронизации тестовых профилей. Кнопка Disconnect деактивирует правила и возвращает браузер к стандартной конфигурации.

Реализованный механизм изоляции действует в пределах браузерного контекста с известными ограничениями: ранее открытые соединения и короткий интервал при аварийном отсоединении отладчика не покрываются полностью. Для полного перенаправления системного сетевого стека операционной системы требуются системные сетевые интерфейсы (TUN/TAP) и системный межсетевой экран. Удаленные серверы фиксируют IP-адрес выходного узла. Подробная спецификация матрицы сетевых сценариев и локальные тесты Chrome приведены в [матрице трафика](docs/traffic-matrix.md#network-guard-and-limits).

### Требования
* **Google Chrome 141+** (или актуальные сборки Chromium / Canary с флагом WebRTC Script Transform).
* Развернутый серверный исследовательский узел `olcrtc srv` (протокол `telemost + vp8channel`).

### Установка из GitHub Releases
1. Скачайте `olcrtc-chrome-extension-0.1.0.zip` со страницы [Releases](https://github.com/15230041523004/olcrtc-chrome-extention/releases).
2. Распакуйте архив.
3. Откройте `chrome://extensions`.
4. Включите **«Режим разработчика»** (Developer mode).
5. Нажмите **«Загрузить распакованное расширение»** (Load unpacked) и укажите папку, в которой лежит `manifest.json`.
6. Закрепите иконку **olcRTC Tunnel** на панели браузера.

### Установка из исходников
1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/15230041523004/olcrtc-chrome-extention.git
   ```
2. Откройте `chrome://extensions`, включите **«Режим разработчика»** и загрузите папку `extension/`.

Сборка zip (без публикации):

```bash
npm test
npm run pack
```

Архив появится в `dist/olcrtc-chrome-extension-<version>.zip`. Тег `vX.Y.Z` на GitHub собирает тот же zip и публикует его в Releases. Тег должен совпадать с `version` в `extension/manifest.json`.

### Проведение теста
1. Откройте интерфейс расширения.
2. Вставьте URI тестовой сессии:
   ```text
   olcrtc://telemost?vp8channel@<ROOM_ID>#<64_HEX_KEY>
   ```
   *(В свернутом виде ключ безопасности маскируется, отображая только идентификатор комнаты)*.
3. Нажмите кнопку **Connect**.
4. После установления соединения (`connected`) и подтверждения этапов рукопожатия тестовый профиль начинает обмен данными через медиаканал.

## 🔬 Технические компоненты исследования

### 1. Инкапсулятор медиакадров (VP8 Carrier Engine)
* **Принцип:** Использование полезной нагрузки сжатого видеокадра в качестве несущего контейнера (carrier).
* **Реализация:** С помощью W3C API `RTCRtpScriptTransform` в отдельном Web Worker расширение перехватывает сжатые видеокадры до отправки в сеть. В байты каждого кадра встраивается заголовок эпохи, токен привязки и полезная нагрузка KCP, защищенная контрольными суммами CRC32C.

### 2. Мультиплексирование сетевых потоков (KCP + Smux v2)
* **Принцип:** Обеспечение низкой задержки и устранение Head-of-Line Blocking при передаче множества логических потоков данных.
* **Реализация:** KCP обеспечивает надежную доставку с контролем потока и минимальными накладными расходами. Протокол Smux v2 организует параллельные виртуальные каналы поверх одного KCP-соединения с расширенным окном **4 МБ** и порогом апдейта **256 КБ**, что ликвидировало просадки скорости при передаче тяжелых медиасегментов.

### 3. Оптимизация пула соединений (Warm-Socket Fast-Path)
* **Принцип:** Минимизация латентности при интенсивных сериях сетевых запросов.
* **Реализация:** Встроенный пул соединений удерживает до **240 сокетов** (до **32 сокетов на один домен**) с таймаутом бездействия 3 минуты. При наличии готового открытого сокета запрос исполняется напрямую в обход очереди `HostGate` со снижением задержки с 2400 мс до ~250 мс.
* **Реализация:** Встроенный пул соединений удерживает до **240 сокетов** (до **32 сокетов на один домен**) с таймаутом бездействия 3 минуты. При наличии готового открытого сокета запрос исполняется напрямую, минуя очередь `HostGate`, со снижением задержки с 2400 мс до ~250 мс.

### 4. Кэширование и дедупликация (SWR & GraphQL Coalescing)
* **Принцип:** Снижение дублирующей нагрузки на медиаканал.
* **Реализация:**
  * **In-Flight Coalescing:** Параллельные одинаковые запросы GET и безопасные идемпотентные GraphQL POST-запросы на чтение объединяются в один запрос. Запросы типа `mutation` строго изолированы и выполняются индивидуально.
  * **Stale-While-Revalidate (SWR):** Статические ресурсы мгновенно отдаются из ОЗУ (0 мс), а их актуальность фоново верифицируется через канал.
  * **Локальные ответы (Fast-Mock):** Вспомогательные телеметрические запросы и preflight CORS-запросы обрабатываются локально за 0 мс без загрузки транспортного канала.

### 5. Изоляция контекста браузера (Network Context Isolation)
* **Принцип:** Гарантия чистоты сетевого эксперимента и предотвращение побочных соединений мимо исследуемого экспериментального канала.
* **Реализация:**
  * **Подавление фоновых утечек:** Через CDP во вкладки внедряется сценарий нейтрализации `RTCPeerConnection` (предотвращение неконтролируемых STUN-соединений), блокируются непроксируемые WebSockets и изолируются ServiceWorker.
  * **Dynamic Network Guard:** Использование правил `declarativeNetRequest` (DNR) с динамическими исключениями для активных отладочных сессий.
  * **Синхронизация профиля:** Адаптация координат геолокации, таймзоны IANA, языка (`Accept-Language`) и Client Hints под узел выхода для предотвращения региональной рассинхронизации.

## 📋 История изменений и ключевые улучшения (Changelog)

### Версия 0.2.2 — 4K YouTube, стабильный отпечаток и Connect без зависания
* **Устранение потолка 17 Мбит/с:** Внедрены SDP-модификаторы пропускной способности (`b=AS:120000`, `b=TIAS:120000000`, `x-google-max-bitrate=120000;x-google-start-bitrate=50000`), слоты SFU Telemost переведены в режим 4K/1080p, тактирование несущей повышено до 60 FPS, а параметры энкодера `RTCRtpSender` расширены до 120 Мбит/с. Реальная скорость скачивания чанков возросла до ~80 Мбит/с.
* **Упреждающий прогрев TLS-сокетов (Proactive TLS Pre-warming):** Фоновое создание авторизованных сокетов TLS 1.3 к активным хостам видео-CDN с поддержанием пула тёплых соединений.
* **Устранение задержек и `fetch.gone`:** Исправлен таймаут `headerTimeoutMs` для повторно используемых сокетов (снят искусственный лимит 3 с, приводивший к ложному разрыву рабочих соединений при подготовке 4K-сегментов), задержка Early-Idle для медиапотоков сокращена до 600 мс, добавлен парсинг трейлеров чанков RFC 9112.
* **Стабильный отпечаток:** Canvas/WebGL/Audio и прочие поля профиля считаются из настроек. Connect и смена IP выхода их не пересоздают. Экран и цветовая схема по умолчанию не трогают окно.
* **Connect больше не зависает на тяжёлой вкладке:** Дочерние iframe/worker резюмятся сразу, паузы Fetch не блокируют настройку отладчика, каждая команда ограничена 3 с. Одна вкладка (например Gemini) не удерживает туннель.

### Версия 0.2.1 — Оптическая диафрагма, сворачиваемые настройки и индикатор скорости в Мбит/с
* **Единая оптическая диафрагма:** Устранено паразитное вращение и скачки между несвязанными иконками. Иконка представляет собой механическую ирисовую диафрагму с внешним зубчатым ободом, плавно открывающуюся по 13 шагам рукопожатия и переходящую в чистый лазерный луч при подключении.
* **Сворачиваемый блок Settings:** Секция настроек получила интерактивный заголовок с анимированным шевроном и сохранением состояния сворачивания в локальном хранилище.
* **Индикатор пропускной способности (Throughput Badge):** Добавлена опция отображения реальной скорости обмена в Мбит/с (Mbps) на бейдже тулбара и в заголовке статуса попапа (`↓in ↑out Mbps`).
* **Англоязычная локализация тем:** Названия тем в селекторе приведены к чистому английскому виду (`Wormhole`, `Optics (Badge)`, `Radar`) с темой по умолчанию `Wormhole`.

### Версия 0.2.0 — Динамическая индикация и расширенная совместимость
* **Динамическая система тем иконки (Toolbar Indicator Themes):** 3 переключаемые векторные темы в настройках с рендерингом через `OffscreenCanvas` в Service Worker и 0% CPU при бездействии.
* **Расширенная совместимость форматов и CDN:** Распознавание форматов изображений AVIF, SVG, BMP и оптимизация обработки тяжелых медиасегментов.
* **Оптимизация энергопотребления:** Анимационный цикл активен только во время рукопожатия и активной передачи пакетов.

### Версия 0.1.0 — Исследовательский прототип
* **Инкапсуляция медиапотоков WebRTC (VP8 Carrier):** Исследовательский конвейер передачи сетевого трафика через видеоконференции с контролем целостности CRC32C.
* **Мультиплексирование KCP + Smux v2:** Низколатентная доставка пакетов и окно 4 МБ для высокой пропускной способности.
* **Изоляция сетевого контекста (Network Guard):** Блокировка прямых утечек в тестовом профиле Chrome и синхронизация геолокации, таймзоны, языка и Client Hints под узел выхода.
* **TLS 1.2 + TLS 1.3 в WebAssembly-клиенте Rustls:** Двойное согласование версий и полный набор шифров для совместимости с узлами, требующими TLS 1.2.
* **Fresh Google session (по умолчанию выкл.):** Опциональная изоляция профильных Google-куки на Connect; выключенный режим сохраняет текущий логин.

## 🎛 Интерфейс и телеметрия

* **Индикатор стадий подключения:** Заголовок сворачиваемого статуса отображает шкалу из 13 светящихся кубиков, визуализирующих пошаговый прогресс установления соединения (сигнализация, токены, трансформация, медиапотоки).
* **Сворачиваемая строка URI:** Отображает только идентификатор комнаты Телемоста, скрывая ключ безопасности и разворачиваясь для редактирования по клику.
* **Диагностический режим (Debug & Logs):** По умолчанию отключен для минимизации накладных расходов CPU на логирование. При необходимости включается для отладки протокола и экспорта отчета в JSON.
